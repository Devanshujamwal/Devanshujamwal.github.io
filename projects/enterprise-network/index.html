01 / Overview

Project overview

The project models a company network spanning multiple sites. My documented contribution focused on Site 3 IPv4/IPv6 addressing and network documentation, while the broader lab demonstrates how routed sites, switching, addressing, and network services work together.

02 / Objective

What the design needed to accomplish

Build a structured multi-site network that supports end-to-end communication while keeping addressing organized, scalable, and understandable during troubleshooting.

03 / Architecture

Conceptual architecture

Calgary HQLAN / switching
Inter-site routingOSPF / routed links
Red Deer + EdmontonRemote LANs

04 / Implementation

Key implementation work

  • Designed and documented Site 3 addressing from the assigned 10.9.0.0/18 space using VLSM.
  • Documented IPv6 global-unicast, link-local, and default-gateway assignments.
  • Worked within a broader design using VLANs, OSPF, DHCP, NAT, and DNS concepts.

05 / Troubleshooting

How I approach network issues

I start with host addressing and default gateways, then move through interface/VLAN state, routing, and finally higher-level services. A documentation review also exposed an interface/gateway inconsistency in the Site 3 report, which I treat as a documentation discrepancy rather than claiming an unverified live fault.

06 / Validation

Evidence and scope

The original Packet Tracer project and project PDFs are preserved in the GitHub repository. I deliberately avoid inventing CLI output that is not preserved in the source material.

The value here is the documented design, addressing work, and troubleshooting reasoning—not fabricated test evidence.

07 / What I learned

What the project reinforced

Subnet planning, consistent addressing, routing, switching, and network services are tightly connected. Accurate interface and gateway documentation can make the difference between fast troubleshooting and unnecessary guesswork.
