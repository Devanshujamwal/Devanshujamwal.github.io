01 / Context

Overview

An academic network infrastructure project. My documented contribution focused on Site 3 IPv4/IPv6 addressing and network documentation, while the broader lab demonstrates how routed sites, switching, addressing, and common services work together.

02 / Intent

Objective

Connect multiple sites and document how addressing, routing, and local services support end-to-end connectivity.

03 / System design

Architecture

Conceptual multi-site topology illustrating routed connectivity, local switching, addressing, and network services used in the academic design.

04 / Toolkit

Technologies

  • Cisco
  • Packet Tracer
  • TCP/IP
  • IPv4
  • IPv6
  • VLSM
  • VLANs
  • OSPF
  • DHCP
  • NAT
  • DNS

05 / Build notes

Implementation

01

IPv4 subnet design

Designed and documented Site 3 addressing from the assigned 10.9.0.0/18 space using VLSM for LANs of different sizes.

02

IPv6 addressing

Documented IPv6 global-unicast, link-local, and default-gateway assignments as part of the dual-stack design.

06 / Diagnostic reasoning

Troubleshooting

I use a layer-by-layer process: confirm endpoint addressing and gateways, verify VLAN/interface state, review routing, then move to DHCP, DNS, NAT, or application services. A Site 3 report inconsistency is documented as a documentation discrepancy rather than an unverified live fault.

07 / Verification

Validation

The repository preserves the original Packet Tracer project and supporting PDFs. The portfolio does not invent ping, traceroute, or routing-table output that is not preserved in the project material.

08 / Reflection

What I Learned

The project strengthened my understanding of how subnet planning, consistent addressing, routing, switching, and shared services depend on one another. It also reinforced why accurate documentation matters during troubleshooting.
