01 / Overview

Project overview

Developed as a three-person academic project. The application uses a Book class for record behaviour and a CLI layer for catalogue operations. The repository was later refreshed for clearer documentation and a more reliable local workflow.

02 / Objective

What the application does

Load and save a catalogue, view records, borrow and return books, find records by ISBN, and provide librarian-only add/remove operations.

03 / Architecture

Application structure

library_app.pyCLI + catalogue operations
book.pyBook model
books.csv + testsPersistence + checks

04 / Implementation

Key implementation areas

  • book.py encapsulates ISBN, title, author, genre, and availability.
  • library_app.py handles load/save, lookup, menu, and catalogue operations.
  • test_book.py now contains repeatable assertions for key Book-model behaviour.

05 / Troubleshooting

Portfolio refresh and debugging

The original application stored the selected catalogue filename in local scope while the save path referenced it elsewhere. During the refresh, I traced that data flow and changed the design so the filename is passed explicitly to saving.

06 / Validation

What is actually checked

The refreshed repository includes a sample catalogue and assertion-based Book-model checks covering construction, borrowing, returning, setters, title matching, and genre handling. It does not claim complete automated coverage of every CLI path.

07 / What I learned

Maintainability matters

The project reinforced encapsulation, variable scope, file persistence, repeatable testing, and the importance of clear ownership when working in a shared codebase.
