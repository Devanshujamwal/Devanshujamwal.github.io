01 / Context

Overview

A command-line Python application developed as a three-person academic team project. The repository contains the Book model, application workflow, tests, sample catalogue, and project material.

02 / Intent

Objective

Apply object-oriented programming to library records and build a small application for loading, viewing, borrowing, returning, adding, removing, and saving books.

03 / System design

Architecture

The application separates catalogue operations from the Book model and uses a small CSV-style file for persistence.

04 / Toolkit

Technologies

  • Python
  • OOP
  • File I/O
  • Input validation
  • Debugging
  • Assertions
  • Git/GitHub

05 / Build notes

Implementation

01

Book model

book.py encapsulates ISBN, title, author, genre, and availability with methods for borrowing and returning.

02

Catalogue operations

library_app.py handles loading/saving, ISBN lookup, menu flow, and librarian operations.

06 / Diagnostic reasoning

Troubleshooting

The original source had a catalogue filename/scope issue in the save path. During the portfolio refresh, I traced the data flow and changed the design so the selected filename is passed explicitly to saving.

07 / Verification

Validation

The refreshed repository includes a sample catalogue and assertion-based Book-model checks covering construction, borrowing, returning, setters, title matching, availability, and genre handling. It does not claim complete automated coverage of every CLI path.

08 / Reflection

What I Learned

The project reinforced encapsulation, variable scope, file persistence, repeatable testing, and why explicit data flow makes software easier to debug.
