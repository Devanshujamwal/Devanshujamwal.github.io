01 / Overview

Project overview

This lab connects Windows/Linux virtual machines with Azure networking, security controls, access management, storage, and monitoring concepts. The emphasis is infrastructure operation and troubleshooting rather than application development.

02 / Objective

What I wanted to understand

Build practical familiarity with how Azure compute, networking, permissions, storage, and monitoring work together so issues can be diagnosed systematically.

03 / Architecture

Conceptual architecture

Virtual NetworkSubnets + NSGs
Windows / Linux VMsCompute + guest OS
Monitor + Log AnalyticsOperational visibility

04 / Implementation

Key areas practised

  • Windows and Linux virtual-machine administration scenarios.
  • Virtual Networks, subnet concepts, and Network Security Groups.
  • RBAC and least-privilege access concepts.
  • Azure Storage, Azure Monitor, and Log Analytics.

05 / Troubleshooting

Layered cloud troubleshooting

I separate resource state, network reachability, NSG behaviour, guest-OS state, permissions/RBAC, and monitoring data. That prevents a permissions problem from being mistaken for a network problem—or vice versa.

06 / Validation

Scope and validation

This case study represents academic hands-on work. It does not claim ownership of production subscriptions, customer workloads, or undocumented deployment results.

07 / What I learned

Infrastructure is a system

A cloud VM is only one component. Networking, identity, permissions, storage, operating-system configuration, and monitoring all determine whether the environment is reachable, secure, and supportable.
