01 / Overview

Project overview

The lab focuses on Windows/Linux event visibility, Wazuh/SIEM concepts, network telemetry, and the reasoning process behind reviewing security alerts.

02 / Objective

What I wanted to learn

Understand how endpoint and network telemetry becomes useful investigation context and why an alert must be validated before it is treated as a confirmed incident.

03 / Architecture

Monitoring flow

EndpointsWindows / Linux events
Wazuh / SIEMCentralized review
TriageContext + investigation

04 / Implementation

Key areas practised

  • Windows/Linux security-event and endpoint-monitoring concepts.
  • Wazuh/SIEM fundamentals for centralized event review.
  • Wireshark and firewall concepts for network context.
  • Timestamp, source, and related-event review before conclusions.

05 / Troubleshooting

Validate telemetry first

Before interpreting a missing or unexpected event, I check the endpoint/source, agent or collection path, timestamps, ingestion, and related network/security context.

06 / Validation

Evidence boundary

This is cybersecurity lab work, not professional SOC experience. The case study intentionally avoids fabricated detections, incident metrics, or customer outcomes.

An alert is a starting point for investigation, not proof by itself.

07 / What I learned

Context changes the meaning of an alert

Reliable investigation depends on telemetry quality, endpoint information, network evidence, and a repeatable process for separating what is observed from what is inferred.
